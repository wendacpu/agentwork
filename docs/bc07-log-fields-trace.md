### 2.1 三个嫌疑的结论

**「看点提取」不是根因。** h1 的 value、`relation=core`、`eliminated` 的淘汰理由都正确。若看点错，h1 应写成「德文为何是传奇」或「比赛过程」——都不是。

**「选择表达策略」是首错环节。** 不是策略选错名（`疑问留答` 在提示词里有明确门槛「视频确实给答案」），而是**门槛被误判为满足**：
- 提示词只要求「视频确实给答案」，没有要求「答案回答的就是这个疑问」；
- 提示词禁止「为了凑钩子结构去改讲另一个片段」，但没有禁止「**改变主看点内部要素之间的关系**」；
- 所以 core_hook 合法地借用了 h1 里的一对要素（`赢过德文一次` / `称他传奇`），把它们的原有关系（**并列陈述**）替换成新关系（**待解释的反差**），并顺手删掉了唯一能回答这个反差的要素（`德文赢过所有顶尖选手`）。

**「评审」是决定性环节。** 它不只是没拦住，而是**用违规的判定方式放行**：G3 的 `core_covered` 定义里明写「而非仅引用出现过的事实」，评审却用「出现过的一句话能拼成答案」代替了「这个问题被当作主题回答」。它在同一句 reason 里完成了答非所问并判 pass——疑问焦点是「称他传奇的理由」，答案谓词落在「不认为自己更强」。

换句话说：**表达层造了一个视频没问的问题，评审层用视频里答另一个问题的句子把它答了。**

## 3. 不可用理由的三维度拆解

> 人工原话：「视频展示了萨科夫受采访时的真实回应，而不是讲他为什么称德文是传奇。」

### 维度一：这个标题会给用户带来什么预期

- 主体预期：**萨戈夫对德文的历史地位有判断**，判断是「传奇」。
- 内容预期：视频会**论证或解释**「一个刚赢过德文的人，为什么仍把德文供在传奇位」。这是一个**待解的反差**——你都赢过他了，为什么还服他？
- 结构预期：因为标题用了「为何」，读者会等一个**因果解释**，而且这个解释要能回答"为什么打不过/比不过却仍称传奇"。
- 隐含预期（最要命）：视频会以「德文的伟大」为话题。读者点开是要听**德文为什么强**。

### 维度二：为什么该标题会给用户带来这样的预期

四层，逐层可指到字段：

1. **`为何` 的疑问焦点决定了宾语。** 「A 为何仍 X」在中文里是把 X 当成**反常**、把 A 的解释当成**话题**。话题因此从「萨戈夫怎么看自己」滑到「德文凭什么被称传奇」。
2. **标题删掉了唯一答案。** 视频里对「为何称他传奇」的回答是 c3 的后半句「德文赢过世界上所有顶尖选手」。cand-3 把 c3 压缩成「赢过德文一次」，只留了对萨戈夫不利的一半，**把答案那一半删了**。于是标题里的「为何」在标题内部无解——钩子正是靠这个"无解"成立的。
3. **把已给出的结论改写成了待解疑问。** 视频里「德文是传奇」是萨戈夫**主动给出的结论**（ev3，`confidence=grounded`），不是他要论证的题目。N09 的 `strategy=疑问留答` 把它翻成问句，等于向读者承诺「这个结论需要被解释」。
4. **评审没有纠偏，反而把错位写进了自己的判据。** `expected_takeaway.viewing_promise` 写的是「看到萨戈夫解释为何仍称德文为传奇」——评审在判断之前，**已经接受了这个错位的承诺**，所以 G3 没有比对对象。

### 维度三：改哪里，怎么改，能让标题内容更还原视频原貌

**方向：把「反常待解」还原成「结论 + 理由」，不要靠删答案造钩子。**

同一主看点（h1）、同一槽位（core_hook）、同一主旨（t1），忠实的写法是保留因果方向：

- 推荐：**「赢过德文一次，萨戈夫仍称他是传奇」** —— 去掉「为何」，反差保留但不再是悬念；读者预期变成「听他怎么评价」，视频交付的就是这个。
- 备选：「德文赢过所有顶尖选手，我只赢过他一次」 —— 直接给出视频里的因果（c3），比较轴与视频一致。
- 备选（次强）：「萨戈夫：赢过一次不算什么，德文是传奇」 —— 保留归属 + 保留结论，但「不算什么」是加工，需人工确认是否越界。

**结构性改法（不是逐条改文案）：**

| 层 | 改什么 | 为什么改这里 |
|---|---|---|
| N09 表达 | `疑问留答` 的门槛从「视频确实给答案」升级为「**答案必须回答这个疑问**」；并新增一条禁止：不得为造钩子**删除**主看点内部回答该疑问的要素 | 首错点在这里。不删这条，换个视频还会造同类句子 |
| N09 表达 | core_hook 的结构选择加一问：借用的两个要素在原单元里是**什么关系**，标题必须保留该关系（并列就并列，因果就不翻成悬念） | 对应上面"关系被替换"的机制 |
| R01 评审 | G3 对疑问式标题增加固定动作：先写出「该疑问的答案是什么」，再判该答案在视频里是**主题性回答**还是**顺带提及**；顺带提及 → `delivery_supported` 不得为 true | 把 `core_covered` 已有的「而非仅引用出现过的事实」落成可判定动作 |
| R01 评审 | Q3 的「钩子不兑现」目前只扣分不阻断（`issues=[]`、`quality_sum=9` 仍放行），需给一个能进路由的 issue_code | 现在"答非所问"最多扣 1 分，进不了拦截 |
| 规则包 F10 | 现有 F10 只禁「不把问题改为受访者承认」（问题→陈述），需补反向：「**不把受访者的陈述改写为标题的提问**」 | 规则缺口是**方向性**的，只覆盖了一边 |

## 5. 上一轮"修复"为什么没拦住（回答"原因没分析到位"）

上一轮做的三件事，逐条对照本 case：

| 上轮动作 | 实际防住了什么 | 为什么防不住 cand-3 |
|---|---|---|
| 提示词加「受访者解释 vs 客观分析」区分 | 提醒模型别把自述当客观分析 | 模型**两处都写 true**，提示词没有落到可判定字段，模型可以"理解对了但填 true" |
| 程序兜底：任一明确 false 不得被 pass 覆盖 | 自相矛盾（写 false 却判 pass） | cand-3 两项都是 true，**没有 false 可兜** |
| 定向 8 项 + 全量 678 项回归 | 程序接线正确 | 测的是"矛盾结构"，不是"答非所问"，所以全绿也无效 |

**根因不是「评审字段自相矛盾」，而是「两个布尔字段本身没有衡量『疑问是否被回答』的维度」。** 把矛盾当根因，就会做出一个只防矛盾的兜底——三重复测（原任务重评、端到端重跑、第二轮不同口径）都复现同一句标题，正是这个判断错误的证据。

本文件相对上一轮多出的判断：把"答非所问"定位成**可核查的推理错误**（疑问焦点 vs 答案谓词），而不是"语义偏差"这种无法写成判据的描述。
