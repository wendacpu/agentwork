## 一次真实运行长什么样

正常路径（默认关闭 N03V）：

```
N00 → N03 → N04 → N05 → N07 → N09 → N10 → R01 → Q01 → N12
```

启用外部核查且领域允许时，N03 后执行 N03V；高风险结果转人工，其他结果传入后续边界判断：

```
N00 → N03 → N03V → N04 → N05 → …
          └─ 高风险 → pending_human
```

触发重写时（最多两轮）：

```
… → N09 → N10 → R01 → Q01 ──rewrite──→ N09(R02) → N10 → R01 → Q01 → N12
```

出错：

```
任意节点 ──异常──→ X01（技术失败，可续跑）
N06 无可用陈述 ──→ X02（业务停止）
```

## 为什么编号会跳

`N01 / N02 / N06 / N08 / N10 / N11` 在代码里是 **Python 函数内联**，不是独立步骤，所以：
- 调试台看不到它们的独立事件；
- 但在设计文档里它们是独立节点，读文档会找不到对应位置。

这些编号对应代码中的内联处理或借用其他节点事件，不代表独立的模型调用。节点数、事件记录方式可能随实现变化；本表按当前代码位置整理，代码调整后应同步核对。**如果觉得编号记不住，原因是设计上的步骤编号与运行时事件并非一一对应。**

## 建议的记忆方式

不用记编号，记四段：

| 段落 | 包含 | 干什么 |
|---|---|---|
| 读材料 | N00–N03V | 读取材料并按配置选择性核查事实 |
| 划边界 | N04–N06 | 决定哪些能写、必须怎么写 |
| 写标题 | N07–N10 | 选看点、生成、机械检查 |
| 判好坏 | R01–Q01–N12–H01 | 独立评审、程序裁决、交给人 |

编号只在查日志时有用：看到 `N05` 就知道是"边界判错了"，看到 `N03V` 就是"核查结果/高风险转人工"，看到 `R01` 就知道是"评审放水了"。
