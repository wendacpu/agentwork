# 离线对照实验预注册（v1 · 锁定后不得看结果再改）

> **业务规模口径更新：**业务方每天需要撰写标题的视频约 3～4 万条。本文第 6.5 节的 560～640 万条／日、45 秒／条及相关推算使用旧口径，不作为当前业务结论；须重新核算。实验方案如需调整，应按下述版本登记流程处理。

> 状态：**草案待批准**。批准后冻结版本与规则；若中途因故调整任一判据，必须重新登记为 v2 并说明原因，不得静默降低门槛。
> 依据：可信离线产品计划的 C/D 阶段与 [18 条人评根因证据](</Users/wanting/program/复杂 agent/docs/root-cause-18-review-batch.md>)。本文件不产生结论，只锁口径。

## 一、这份协议要回答什么

1. 复杂链路（理解→边界→看点→生成→独立评审→定向重写）相比同模型单次直出，在同等材料与同等展示约束下，能否产出更多可交付标题？
2. 多出来的质量（若有）值多少调用量、Token、延迟和每条可用标题的成本？
3. 改善能否出现在未参与调优的样本上？

不回答、也不得声称：线上 CTR 或线索提升、任一候选可用率、拦截召回率、误拦率。

## 二、样本

### 2.1 开发集（D 集）

- 成员：templates/eval_manifest.json 的 20 条。
- 用途：允许据此修 Prompt 与规则。早期另一个 20 视频批次已有 18 条人评，但与本 D 集仅 3 个视频重合；这些标签只能作为对应历史任务的诊断参考，不能称作 D 集已有 18 条人评，也不能直接用于当前任务计分。
- 结果只算开发集表现，不得当作泛化证据。

### 2.2 验证集（V 集）

- 来源：recent-portrait-300 与主数据集。
- 干净样本核算（只读核实）：排除已进 manifest、已人评、已进金标、已在任意运行库出现过的视频后，主数据集剩 54 条，300 池剩 279 条。
- 抽样规则（待修订，当前不可执行）：原拟按一级领域分层、每领域取 2 条、共 20 条；但 300 池有 21 个一级领域，按字面须 42 条。须先确定覆盖范围与分配办法或调整样本量，登记协议版本后再抽样；不得看模型结果后修改。
- 抽样时点：在跑任何一条模型结果之前确定并写入 templates/validation_manifest.json，只校验成员身份与资产完整性（audit），不查看模型输出后再调名单。
- 若干净样本不足 20 条：如实报告缺口，由本人决定补采；严禁把 D 集样本改名充作 V 集。

## 三、两臂定义

| 项 | 基线臂（B） | 当前臂（C） |
|---|---|---|
| 模型 | 与 C 臂相同生成模型 | 当前配置的生成与评审模型 |
| 输入 | 同一输入快照（完整 ASR/OCR/标题/描述/领域/形态，不截断） | 同左 |
| 生成 | 一次直接生成 3 条 | 现有多节点链路，首轮 3 条 |
| 审核 | 基础审核择一 | 独立评审加程序裁决 |
| 重写 | 无 | 最多现设 2 轮定向重写 |
| 交付 | 1 条系统推荐 | 1 条系统推荐 |
| 展示约束 | 同长度上限、同前缀规则、同问号禁令 | 同左 |

已知不对称，必须如实报告，不得包装成仅架构差异：C 臂拥有更多候选机会、更多审核与重写调用。

## 四、防污染

- 两臂使用不同输出目录与任务库；不覆盖任何历史运行。
- 主实验 Memory 关闭：不注入同视频历史案例、不写案例库、不做批次内学习。
- 冻结并记录：源码指纹、Prompt 哈希、规则版本、模型与参数、输入快照哈希、价格表版本。
- 运行中出现认证、余额、预算上限或源码漂移时立即停止，不挑样本替换。

## 五、人工标注

- 盲评：不显示系统来源、评分、推荐理由、模型身份；只给原始材料与标题。
- 判法沿用三档锚点（可用 / 勉强通过 / 不可用），与评测规范一致。
- 数量：每臂每视频评 1 条；D 集最多 40 条，V 集最多 40 条。不评全部中间候选。
- 编辑后通过要单独记录最终标题，但不计入生成臂的成功。
- 单标注时只报告单标注结果，不计算也无法计算 kappa。

## 六、指标

| 指标 | 定义 | 分母 |
|---|---|---|
| 严格可用产出率 | 该视频系统推荐的原始标题被评为可用 | 预注册视频全集 |
| 含勉强可用率 | 推荐被判可用或勉强通过 | 同上 |
| 推荐准确率 | 被评价的系统推荐中可用的占比 | 仅已评价的推荐 |
| 未产出推荐率 | 技术失败 / 业务停止 / 无推荐 | 全集，分别列出 |
| 首轮可用率 | 未经重写的第一轮结果被判可用 | 全集 |
| 超长流入率 | 最终交付标题超过长度上限 | 已交付推荐 |
| 成本与延迟 | 调用次数、Token、墙钟耗时、每条可用标题成本 | 全集 |
| **自动放行占比** | 被判为"可直接发布、无需人审"的占比 | 全集 |
| **自动放行段错误率** | 自动放行里被判"不可用"的占比 | 仅自动放行 |
| **每千条人审分钟** | 人工判定总耗时 ÷ 交付条数 × 1000 | 全集 |

不得输出：任一候选可用率、召回率、误拦率（本期只评推荐，不评全部候选）。

> 自动放行两项当前恒为 0（本系统所有候选都要人工确认），它们是**为百万级规模预留的口径**。
> 离线阶段只能模拟：对同一批结果套不同放行阈值，画「覆盖率 — 精度」曲线，看趋势，不看绝对值。

## 六点五、百万级量级的统计限制（不得越过）

适用规模 560–640 万条/日、人工 45 秒/条，意味着两件事：

1. **人工不可能全量审。** 待审比例 p 对应人力 = 600万 × p × 45秒 ÷ 8小时：
   p=10% ≈ 937 人，p=1% ≈ 94 人，p=0.1% ≈ 9 人。**待审率必须压到 0.1% 量级才有意义。**
2. **95% 精度在百万级等于每天约 30 万条错误放行。** 自动放行要的是 99.9%+。

因此，20 条样本能说的话极其有限。若 20 条全部无严重错误，错误率的 95% 置信上界仍约为 **14%**：

| 样本量（全对时） | 错误率 95% 上界 |
|---:|---:|
| 20 | ≈14% |
| 100 | ≈3.0% |
| 500 | ≈0.6% |
| 3,000 | ≈0.1% |

**结论：离线 20–40 条只能验证机制与方向，不能推断百万级放行率，也不能作为自动放行资格。**
自动放行资格必须由线上 shadow 跑量 + 抽检积累，样本量至少数千条。

## 七、决策规则（看结果前锁定）

1. 资格：身份与标签完整、无错配；已知确定性安全绕过为 0；最终交付超长流入为 0。不满足则实验作废，修完重跑。
2. 开发集晋级：D 集上 C 臂严格可用视频数比 B 臂至少多 2/20（+10pp），且已确认的严重事实风险不增加，才允许消耗 V 集。否则最多再修一轮已确认共因，仍不达标则停止扩复杂链路。
3. 验证集交付：V 集上 C 臂同时满足以下四条，才可作为第一版离线试用交付：
   - 至少 14/20 个视频有严格可用的系统推荐；
   - 推荐准确率不低于 90%；
   - 首次技术失败不超过 1/20；
   - 已确认严重事实风险推荐为 0。
4. 不达标处理：
   - 质量不优于基线且成本更高：采用简单基线或缩窄可交付领域；
   - 质量更好但成本过高：报告每新增一条可用标题的额外成本，由本人决定是否继续投入；
   - 只看 V 集结果后再调规则：V 集转为开发集，必须另选新验证集，不得用同一批宣布泛化成功。
5. 统计限定：20 条样本置信区间很宽，结论只能表述为初步证据，不得宣称 95% 可靠或统计显著。
6. **不得用离线结论批准自动放行**：本协议任何达标结果只支持"人工辅助 + 高风险强制人审"的试用形态；自动放行需另立线上 shadow 方案与数千条以上的抽检证据。

## 八点五、预算估算（待批准，非承诺）

依据本批实测：20 视频累计成功模型回复 **159 次**，prompt **3,854,552** tokens、completion **246,860** tokens（含重试与重写）。折算约 **7.95 次调用 / 视频、192.7K prompt / 视频、12.3K completion / 视频**。

| 项 | 测算 | 估算量 |
|---|---|---|
| 当前臂 20 条（开发集） | 实测单价 × 20 | ≈ 3.86M prompt / 0.25M completion / 159 次调用 |
| 当前臂 20 条（验证集） | 同上 | ≈ 3.86M prompt / 0.25M completion / 159 次调用 |
| 基线臂 40 条 | 直出 3 条 + 基础审核 ≈ 2 次/视频 | ≈ 0.8–1.2M prompt / 0.08M completion / 80 次调用 |
| **合计** | | **≈ 8.5–8.9M prompt / 0.6M completion / ≈400 次调用** |

另加 3 视频冒烟 ≈ 30 次调用。

费用需按当前定价折算；本文件不写未经核实的单价。建议预算上限 = 折算金额 × 1.3（覆盖重试与解析失败），并在跑批脚本里设硬上限，超限即停。
