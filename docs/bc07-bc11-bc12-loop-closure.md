## 1. 萨戈夫赛后表态：评审缺少标题承诺与视频交付的结构化对照

### 1.1 案例速查表

| 字段 | 内容 |
|---|---|
| 案例编号 | BC07（案例库已有登记，状态由「待验证」更新为「已验证」） |
| 任务类型 | 单视频标题生成（采访表态类资讯） |
| 用户输入 | 萨戈夫赛后采访视频：谈与德文的交手经历、称德文是传奇、表示不认为自己已经更强 |
| Agent 输出（问题期） | 「赢过德文一次，萨戈夫为何仍称他传奇」——评审在内容交付与承诺维度的两项布尔判断（视频是否交付标题所述内容、标题是否覆盖视频核心）均为通过，候选放行 |
| 人工修改 | 判定为不可用；理由原文：「视频展示了萨科夫受采访时的真实回应，而不是讲他为什么称德文是传奇」 |
| 问题环节 | 独立评审阶段，内容交付与承诺维度；归因于裁决域；修复回退指向候选生成与看点提炼 |
| 问题原因 | 评审对「标题承诺—视频交付」的核对没有结构化载体，两个布尔结论由模型自由填写；采访类内容的兑现判定未区分「受访者自述经历」与「标题暗示的对他人地位的原因分析」两个视角 |
| 影响指标 | 候选级误放率；评审布尔结论与人工判定的一致率 |
| 修改方案 | 强制填写承诺对照结构（七字段）+ 固定「先对照、后判定」的顺序约束 + 采访/观点类兑现视角区分条款 + 禁止机械否决疑问式标题 |
| 回归测试结果 | 离线回归全部通过；隔离批次复测三条候选全部通过自动评审；人工复核三条全部判定可用 |

### 1.2 闭环过程

**发现问题。** 人工复核打回了系统放行的候选，理由指向标题承诺与视频实际内容的视角错位：视频呈现的是萨戈夫受访时的表态记录，并非一段「为何称德文是传奇」的原因分析；标题向读者承诺了后者，属于货不对板。同期存在反向问题——部分合理的疑问式标题被评审仅因「含有疑问词」而否决（科普等以回答问题为核心的视频恰恰适用该句式），人工明确纠正了这一判定倾向。

**判断问题环节。** 误放与误拦指向同一环节：独立评审的内容交付与承诺维度。该维度的判定没有可核对的中间产物，结论完全依赖模型直觉。

**查看日志和人工反馈。** 任务事件流中，该维度的两项布尔判断均为通过，与人工结论直接矛盾，且无任何配套核对记录可供追溯。决定性的补充证据来自一次对照复测：在仅调整提示词、不改判定机制的前提下，同一问题标题在后续两次生成中均再次出现并再次被放行——证明该缺陷不属于「模型未被告知」，而属于「判定过程缺乏强制结构」，提示词层面不可修复。

**定位原因。** 评审在判断「标题是否兑现」时缺少结构化对照载体，两个布尔结论无约束填写；采访与观点类内容的兑现判定未建立视角区分——受访者对自身经历与态度的解释，不自动构成对他人身份、成就或地位的原因分析，相关事实在视频中出现也不等于承诺兑现。

**确定修改方案。** 三项配套改动：其一，评审对每条候选强制输出承诺对照结构，含七个字段——标题具体承诺、触发该预期的标题措辞、视频实际交付、对应证据摘录、证据实际回答的问题、两者对齐结论（匹配/不匹配/不确定）、以及解释；其二，判定顺序固化为「先完成对照、再下结论」：对齐结论为「不匹配」时，交付判断必须为否定、维度结论必须为「需修改」；为「不确定」时必须转人工；为「匹配」时仍须独立判断核心覆盖——布尔结论不再能绕过对照直接给出；其三，判据明确两条：不得仅凭疑问词否决标题（视频确实以对应问题的回答为核心时应予通过）；采访/观点内容须区分自述视角与原因分析视角。

**小流量测试。** 在四条视频的隔离批次（含本案例视频）复测：三条候选（14/17/16 字）全部通过自动评审，任务路由为正常交付，系统推荐第二条。生成与复核两侧的主旨契约一致性校验同时通过。

**效果达标后放量。** 人工复核三条全部判定可用：

| 候选 | 标题 | 人工判定 |
|---|---|---|
| 候选一 | 萨戈夫：不认为自己已强于德文 | 可用 |
| 候选二 | 萨戈夫称德文是传奇，不认为自己更强 | 可用 |
| 候选三 | 赢过德文一次，萨戈夫仍称他是传奇 | 可用 |

人工终稿「萨戈夫赛后：我不认为已强于德文」与候选一同向（补充「赛后」场景词、改第一人称）。该案例闭环完成。

## 2. 南非偷看球赛：三个独立缺陷叠加导致的零交付

### 2.1 案例速查表

| 字段 | 内容 |
|---|---|
| 案例编号 | BC11（案例库新增登记） |
| 任务类型 | 单视频标题生成（时事新闻类） |
| 用户输入 | 南非两员工上班时间偷看球赛、被球场大屏拍到后转身装作工作的新闻视频 |
| Agent 输出（问题期） | 以「两员工偷看球赛」为主旨的三条候选全部被判「引用内容超出允许范围」而废弃，视频零交付；同时存在日期限定误报与超长候选（21–27 字，上限 20）直送人工评审台 |
| 人工修改 | 「两员工偷看球赛」方向候选人工判定全部可用（历史记录：该方向候选被系统全数否决，人工全部判可用）；超长候选人工全数拒绝，理由「字数超了」，并明确流程要求：超长标题不应进入人工评审台 |
| 问题环节 | 三处独立：机械校验（引用合法性允许集合的构造）、边界限定类型划分（产出与消费两端）、交付路由（超长候选无独立处置通道） |
| 问题原因 | 其一，引用合法性校验维护的允许集合只收录语义分析产出的内容单元，不含结构看点单元——绑定结构看点的候选恰恰指向主看点，却被整体判为无效引用；其二，「写到时才需核对」的条件（报道日期与事件日期的区分）被混入「必须写出」的限定清单，标题不写日期被误报缺限定；其三，超长属于可自动修复的机械缺陷，但评审台取数未做隔离 |
| 影响指标 | 单视频交付率（零交付）；首推严格可用率；人工评审台有效注意力占比 |
| 修改方案 | 允许集合统一（语义单元 ∪ 结构看点 ∪ 边界已表态单元 − 明确排除项）；限定拆分为三类（须写出 / 写到时不得写错 / 纯背景）；超长候选只读隔离并拒绝评审提交 |
| 回归测试结果 | 原视频端到端复测：日期误报未复现；「两员工偷看球赛」方向两条候选通过自动评审；三条超长进入只读区；人工判定两条可用、超长三条在只读区被拒 |

### 2.2 闭环过程

**发现问题。** 三个缺陷各有暴露路径。「偷看球赛」候选被全数否决由人工复核发现——复核员判定该方向标题可用，回查系统结论为全部废弃，形成直接矛盾。超长问题由复核员以流程指令形式提出：「字数超了的标题我这里肯定不会判通过，就不要送到评审台上了」——该指令本身转化为待办需求。日期误报在比对「系统拦截理由」与「标题实际内容」时确认：标题不含任何日期表述，却被报「缺少日期限定」。

**判断问题环节。** 三个缺陷相互独立、互不为因果，需分别归因后并行修复：引用合法性属于机械校验层的集合构造缺陷；日期误报属于边界限定语义的类型缺失（产出端写入位置错误，消费端按最严口径执行）；超长属于交付路由层的通道缺失。

**查看日志和人工反馈。** 任务事件流显示，候选绑定的内容单元来自结构看点提炼（以对话轮次与叙事轴为标识），而允许集合仅收录语义分析单元（以语义单元编号为标识）——两套标识体系不互通，导致绑定结构看点的候选全部被判「不在当前任务范围」；边界输出中，「10月28日为报道日期，非事件发生日期」这条旨在防止写错的提醒，被存放于「必须表达的限定」字段；评审台批次中超长候选与可评候选混排，人工需逐条处理本不应到达的标题。

**定位原因。** 允许集合的构造在初评与复评各维护一份且口径不一，均遗漏结构看点来源；限定要求无类型体系，「不要写错」与「必须写出」共用一个字段，下游只能按最严格语义执行；超长候选名义上走自动压缩重写通道，实际评审台取数未做前置过滤。

**确定修改方案。** 三处分别修复：其一，允许集合统一为「语义单元 ∪ 结构看点 ∪ 边界已表态单元 − 明确排除项」，初评与复评共用同一构造；其二，限定拆分三类——须写出的限定（不表达即错误）、写到时才适用的条件（不写不触发，写入后须核对，日期区分归入此类）、纯背景信息（不要求表达）；其三，超长候选移入只读诊断区（失败轨迹），交付后端拒绝针对该类候选的评审提交，评审列表以显著标识呈现，不再占用人工评审额度。

**小流量测试。** 原视频隔离批次端到端复测：此前的日期误报未再出现；两轮批量评审回复结构无效后，逐候选回退机制成功恢复评审；产出结果——「南非两员工上班偷看球赛被球场大屏抓包」（18 字）与一条压缩重写候选（20 字）通过自动评审，三条 21 字以上候选全部进入只读区。

**效果达标后放量。** 人工复核判定两条可用；三条超长在只读区被拒——拒绝行为发生在诊断区域，不再消耗人工评审额度，验证隔离机制生效。人工终稿「南非两员工上班偷看球赛被大屏抓包」即系统通过评审的候选一删去「球场」二字（16 字），主旨方向完全一致。该案例闭环完成。

## 3. 小包装商业观察：程序侧强制标记覆盖评审模型结论——三层递进的归因与修复

本案例为三者中归因链最长的一个：最初被怀疑的环节（评审模型过严）最终被证明不是根因，真正的错误在程序裁决层。

### 3.1 案例速查表

| 字段 | 内容 |
|---|---|
| 案例编号 | BC12（案例库新增登记） |
| 任务类型 | 单视频标题生成（个人账号商业观察类） |
| 用户输入 | 个人账号「感性城市SCity」发布的城市商业观察视频：小包装、小样等迷你规格商品为何成为消费热点及其商业逻辑 |
| Agent 输出（问题期，分阶段） | 早期：生成将创作者账号名逐字写入标题（账号名本身占六七字，20 字上限无法容纳）；中期：候选「商业观察：博主拆解小包装小样为何走热」等九条全部被「来源归属缺失」判定拦截转入重写，视频零交付 |
| 人工修改 | 九条候选人工判定全部可用；终稿「商业观察：小包装走红背后的消费逻辑」 |
| 问题环节 | 三层递进：边界判定（归属建议措辞生成过严）→ 独立评审（归属判据词法化）→ 程序裁决（词法强制标记无条件覆盖评审结论，根因） |
| 问题原因 | 其一，边界将创作者账号名整串写入「建议归属措辞」字段（该字段语义为「标题宜出现此词」，账号名无法纳入 20 字标题，构成事实上的必死约束），且对博主自述创作方法设了归属要求；其二，评审以「主体+转述动词」的词法匹配判定归属是否表达，不认身份称谓、内容性质前置与演示动词；其三，程序侧词法标记在注入前不做归属线索核对，注入后无条件改写评审模型已给出的合格结论 |
| 影响指标 | 归属类误拦率（全库反向统计：126 条人工可用标题中 74 条被拦，误拦率 59%；其中来源归属缺失 25 次、限定缺失 23 次，另有 19 条为评审结构失败被错误计入标题缺陷）；单视频交付率；重写轮次与模型调用成本 |
| 修改方案 | 四步递进：边界归属措辞规范化；评审归属判据单标准化；程序预判的归属核对结果随评审输入下发；程序标记前置归属线索核对（评审合格结论不再被覆盖） |
| 回归测试结果 | 离线回归 942 项全部通过；小包装终验两条通过自动评审、交付路由正常；人工复核三条全部判定可用（当日完成） |

### 3.2 闭环过程

**发现问题。** 由「人工可用与系统全拦」的反差触发。人工复核判定「商业观察：小包装小样为何成新热点」类标题可用，系统却将九条候选全部转入重写。用户随后确立排查方法论：以人工判为可用的标题为样本反向核对系统判定（而非仅分析被拒的坏标题）。据此完成全库反向统计——261 条可匹配的人工判定中，126 条人工可用，其中 74 条被系统拦截，误拦率 59%；拦截理由分布中「来源归属缺失」（25 次）与「限定缺失」（23 次）为两大来源，另有 19 条实为评审输出结构失败、却被错误计入标题缺陷。该统计确认问题属于判定规则的系统性过严，而非个别案例。

**判断问题环节。** 症状横跨三层。最初怀疑为评审模型判据过严（提示词层），逐层排查后确认根因在程序裁决层。

**查看日志和人工反馈（本案例的决定性步骤）。** 调取评审阶段的输入输出原文快照逐条对照后发现：评审模型在最近数轮中已判定归属合格，判定理由原文为「标题以『博主』归属作者观点，未写成已证实规律；小包装小样成热点为博主分析框架，有ASR与简介支持」；但程序侧的词法强制标记以「主体+转述动词（称/表示/报道）」为判据复查，未命中（「博主拆解」的「拆解」不在其动词表内），遂注入「来源归属缺失」标记，程序在后续裁决环节将评审模型的合格结论强行改写为需修改——既含「商业观察」又含「博主」的候选同样被拦，即由此机制所致。该方法论结论沉淀为通用排查原则：提示词层面反复调整仍无法改变模型行为时，应首先核查模型结论是否被程序侧覆盖。

**定位原因（三层递进）。** 边界层：建议归属措辞字段被填入账号名整串，形成无法满足的死约束；博主自述创作方法（「用放慢演示让新手看清细节」类陈述）本无警示必要，却被设归属要求，迫使标题写成冗余转述。评审层：归属判定标准退化为词法匹配（要求特定转述句式），与人工口径（「读者是否会误认为官方通报/已核实事实/他人原话」）脱节——标题出现身份称谓、内容性质前置或演示动词时，读者已知这是谁的观察，不构成误认风险。程序层（根因）：词法标记注入前不做归属线索核对，注入后无条件覆盖评审结论——提示词层的任何修复都会被该机制改回。

**确定修改方案（四步递进，每步小流量验证后再动下一层）。** 其一，边界侧规范化：个人账号的建议归属措辞一律使用「博主」类通称，不再填写账号名；博主自述创作方法、拍摄手法不设归属要求。其二，评审判据单标准化：判定「来源归属缺失」的唯一标准为「读者是否会将标题当成官方通报、已核实事实或他人原话」；标题出现发布方身份、内容性质前置或分析框架（商业观察/新闻评论/疑问式分析）、或以「教/演示/实测」标明作者动作时，视为归属已表达，不得再报缺失；建议措辞明确定位为参考而非逐字要求。其三，程序预判下发：机械校验输出归属核对结果（要求归属的短语列表 + 标题中是否已存在归属线索的核对结论），随评审输入下发——归属线索的字面核对由程序完成并作为事实供评审采信。其四，程序标记前置检查（根治项）：词法标记注入前执行归属线索核对（建议措辞主体词出现、身份称谓、性质前置、演示动词任一命中即视为归属已表达）——评审模型的合格结论自此不再被程序覆盖；纯断言式标题（无任何身份或性质线索）仍照常注入标记，保留对事实性风险的防线。

**小流量测试（每轮恰好验证一层）。** 第一轮（提示词层）：教程类视频三条候选全部合格放行（「自述创作方法不设归属要求」生效），小包装仍全拦——证明提示词层修复不构成充分条件，存在更深缺陷。第二轮（增补程序预判下发）：美食类视频两条候选合格放行（「美食博主演示…」不再报缺归属），小包装九条仍被拦，但此时日志显示评审模型判合格、程序标记在改写结论——问题被精确定位于程序裁决层。第三轮（增补标记前置检查）：小包装两条候选通过自动评审、交付路由正常，第三条因「标题承诺的问题视频未真正回答」转入重写（该判定方向正确，属质量把关而非误拦）；离线回归 942 项全部通过。

**效果达标后放量。** 当日完成终验批次人工复核，三条全部判定可用：

## 4. 已知偏差与如实说明

1. **闭环成色差异。** 小包装案例为唯一以「当日最终代码 + 当日复测 + 当日人工复核」完成全程闭环者；萨戈夫案例闭环于四日前代码，南非案例闭环于两日前代码，最后合入的归属放宽未在这两条视频上回访复测。风险评估为低（两条视频的标题分别具有明确转述句式与具体事件主体，新旧判据均放行），但形式上缺最后一环。
2. **推荐排序与人工首选的偏差。** 三例中系统推荐位与人工终稿重合仅一例（小包装推荐候选一、人工选候选二；萨戈夫推荐候选二、人工终稿与候选一同向；南非推荐压缩重写版、人工选原始候选一）。候选池质量达标，推荐排序为独立的后续优化项。
3. **残余分歧（方向为系统更严）。** 小包装案例候选三，系统以「承诺未兑现」判转入重写、人工判可用。该分歧不属误拦，留作评审标准校准的观察样本。
4. **外推性声明。** 三案例的修复效果及其对照视频的隔离批次实测，不构成全量误拦率下降的证据；59% 误拦率为修复前全库统计，整体收敛需不少于十条视频的更大批次复测后方可宣称。README 已同步该口径。
