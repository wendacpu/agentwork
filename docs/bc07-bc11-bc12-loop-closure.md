## 1. 案例一：萨戈夫赛后表态——当「系统放行」和「人工否决」同时出现

| 问题期输出 | 「赢过德文一次，萨戈夫为何仍称他传奇」——通过自动评审并放行 |
| 人工判定 | 不可用；理由原文：「视频展示了萨科夫受采访时的真实回应，而不是讲他为什么称德文是传奇」 |
| 调查后定位的问题环节 | 独立评审阶段——「内容交付与承诺」维度的判定过程 |
| 调查后确认的原因 | 承诺核对无结构化载体，结论由模型自由填写；采访类兑现判定未区分「受访者自述」与「原因分析」视角 |
| 影响指标 | 候选级误放率；评审结论与人工判定的一致率 |
| 最终修复 | 强制承诺对照结构 + 先对照后判定的顺序约束 + 疑问式标题与采访视角判据 |
| 回归结果 | 离线回归通过；隔离批次三条候选通过自动评审；人工三条全部可用 |

### 复盘过程

**第一步：发现问题。** 系统生成了「赢过德文一次，萨戈夫为何仍称他传奇」，并在候选评审中判定通过；人工复核却认为不可用。人工给出的理由是：视频展示的是萨戈夫接受采访时的表态，而不是解释他为何称德文为传奇。这意味着标题可能让读者期待一段原因分析，但视频的核心内容并非这一分析。需要注意的是，虽然这条候选通过了评审，原任务因其他校验问题转入人工处理，并未形成系统推荐。

**第二步：判断问题环节。** 这条标题的争议不在于「萨戈夫」「德文」等事实是否出现，而在于**标题暗示的视频内容与视频实际交付是否一致**。因此，调查重点放在自动评审的「内容交付与核心主旨」审查项：它既要判断视频是否兑现标题带来的观看预期，也要判断标题是否覆盖视频的核心内容。

**第三步：查看评审记录和人工反馈。** 原始记录显示，自动评审对上述两项都给出了肯定结论，而人工认为标题所暗示的原因分析与视频重点不一致。进一步复测中，类似问题标题再次出现并获得通过，说明当时的修改尚未稳定解决这一问题。已有记录支持「评审结论与人工判断不一致」，但不足以断言模型完全没有核对证据，也不能仅凭几次复测就证明任何提示词调整都无效。

**第四步：定位原因并确定修改方案。** 结合人工意见与复测结果，我们将问题收敛为：评审虽然需要判断标题是否兑现，但原先缺少一套便于逐项检查和追溯的对照要求，尤其需要区分采访对象的自我评价与针对他人地位的原因分析。为此，修改后的评审需要先说明标题会让读者期待什么、哪些措辞产生了这一预期、视频实际讲了什么、对应原始证据回答了什么问题，再判断两者是否一致。若视频没有兑现预期，应要求修改；证据不足时转人工；即使内容一致，也仍需判断是否覆盖视频核心。

同时明确：**不能因为标题用了「为何」就直接否决**。如果视频确实回答了标题提出的问题，疑问式标题可以通过；是否合适取决于具体承诺与视频内容，而不是疑问词本身。

**第五步：小流量测试。** 在包含本案例视频的四条视频隔离批次上复测。三条候选（「萨戈夫：不认为自己已强于德文」「萨戈夫称德文是传奇，不认为自己更强」「赢过德文一次，萨戈夫仍称他是传奇」）全部通过自动评审，任务正常交付。

**第六步：人工复核收口。** 复核判定三条全部可用。终稿「萨戈夫赛后：我不认为已强于德文」与系统的候选一同向。系统合格候选池与人工认可完全重合，本案闭环。

## 2. 案例二：南非偷看球赛——三个互不相干的缺陷同时砸在一条视频上

### 案例登记卡

| 字段 | 内容 |
|---|---|
| 案例编号 | BC11（案例库新增登记） |
| 任务类型 | 单视频标题生成（时事新闻类） |
| 视频内容 | 南非两员工上班时间偷看球赛、被球场大屏拍到后转身装作工作 |
| 问题期输出 | 「两员工偷看球赛」方向三条候选全部被判「引用内容超出允许范围」而废弃，视频零交付；另含日期误报与超长候选直送人工评审台 |
| 人工判定 | 「偷看球赛」方向候选全部可用；超长候选全数拒绝（「字数超了」），并提出流程要求：超长不应进入评审台 |
| 调查后定位的问题环节 | 机械校验的引用合法性、边界限定的类型划分、交付路由的超长隔离——三处独立 |
| 调查后确认的原因 | 引用合法性允许集合只收录语义分析单元、遗漏结构看点单元；「写到时才需核对」的条件被混入「必须写出」的限定清单；超长候选无独立处置通道 |
| 影响指标 | 单视频交付率；首推严格可用率；人工评审台有效注意力占比 |
| 最终修复 | 允许集合统一、限定拆分三类、超长只读隔离 |
| 回归结果 | 原视频复测：日期误报未复现，「偷看球赛」两条通过自动评审，超长三条只读隔离；人工两条可用 |

### 复盘过程

**第一步：现象收集——这不是一个问题，是三个。** 人工复核同时暴露了三件反常的事：其一，以「两员工偷看球赛」为主旨的三条候选被系统全部废弃，理由是「引用内容超出允许范围」，而复核员判定这三条全部可用——候选写的明明是视频最核心的画面，「引用不存在」从常识上就不成立；其二，评审台上出现了二十六七字的超长候选（上限 20），复核员逐条拒绝并直接提出流程要求「超长就不要送来」；其三，回查拦截理由时发现一条候选被报「缺少日期限定」，而它的标题里连一个日期都没有。

当时面临一个判断：这三件事是一个根因的三种表现，还是三个独立缺陷碰巧叠加？这决定了修复是「找总根」还是「分头治」。事后证明是后者——但这个结论要靠逐项排查才能下，不能靠猜。

**第二步：追查「引用不存在」的判定依据。** 调出候选的绑定记录与机械校验的允许集合，发现了不互通的两套标识：候选绑定的是**结构看点**（从视频的对话轮次、叙事轴里提炼的内容，标识形如「第二轮对话」）；而允许集合里装的全是**语义分析单元**（从内容理解阶段产出的语义块，标识是另一套编号）。两套体系名字对不上，于是所有绑定结构看点的候选一律判「不在允许范围」——但这些候选指向的恰恰是视频的主看点。缺陷确认在机械校验的集合构造：它只认一种来源。另外还发现初评与复评各自维护一份允许集合、口径还不一致。

**第三步：追查日期误报。** 边界系统的输出里存着一条「10月28日为报道日期，非事件发生日期」的提醒。它的本意是防止写错——标题不写日期就无事，写了日期才需要核对有没有把报道日期当成事件日期。但它被存放进了「必须表达的限定」清单，下游只能按最严口径执行，于是「不写日期」反而成了错误。缺陷确认在限定语义的类型划分：**「必须写出的」和「写到时才需核对的」混在同一个字段里**，没有类型体系。

**第四步：确认超长问题的性质。** 超长在名义上属于「可自动修复」的机械缺陷，本该走自动压缩重写的通道，但评审台的取数逻辑没有做前置过滤，把所有非排除候选都拉了进来——人工在替程序做程序自己该做的事。缺陷确认在交付路由：缺一条独立通道。

**第五步：据此确定修复方案——三处并行、分别验证。** 因为三个缺陷相互独立，修复也分别进行：其一，允许集合统一为「语义单元 ∪ 结构看点 ∪ 边界已表态单元 − 明确排除项」，初评与复评共用同一份；其二，限定拆分三类——须写出的（不表达即错）、写到时才适用的（不写不触发，写入后须核对，日期提醒归此类）、纯背景（不要求表达）；其三，超长候选移入只读诊断区，交付后端拒绝针对它们的评审提交，评审列表以显著标识呈现。

**第六步：小流量测试与放量。** 用原视频做隔离批次端到端复测。此前「不写日期却报缺日期」未再出现；「偷看球赛」方向的「南非两员工上班偷看球赛被球场大屏抓包」（18 字）与一条压缩重写候选（20 字）通过自动评审；三条超长全部进入只读区。人工复核判定两条可用，超长三条在只读区被拒——拒绝行为发生在诊断区域，不再占用人工评审额度。终稿「南非两员工上班偷看球赛被大屏抓包」即通过评审的候选一删去「球场」二字，主旨完全一致。本案闭环。

## 3. 案例三：小包装商业观察——当提示词怎么改都不管用时，该看什么

本案例的调查链最长，也最反直觉：最初被怀疑的环节（评审模型判据过严）最终被证明不是根因。复盘的价值主要在于调查方法本身。

### 案例登记卡

| 字段 | 内容 |
|---|---|
| 案例编号 | BC12（案例库新增登记） |
| 任务类型 | 单视频标题生成（个人账号商业观察类） |
| 视频内容 | 个人账号「感性城市SCity」发布的商业观察：小包装、小样等迷你规格商品为何成为消费热点及其生意逻辑 |
| 问题期输出 | 早期：生成将账号名逐字写入标题（账号名占六七字，20 字上限装不下）；中期：九条候选全部被「来源归属缺失」判定拦截转入重写，零交付 |
| 人工判定 | 九条全部可用；终稿「商业观察：小包装走红背后的消费逻辑」 |
| 调查后定位的问题环节 | 边界归属措辞生成 → 评审判据 → 程序裁决的强制标记——三层递进，根因在最深处的程序裁决层 |
| 调查后确认的原因 | 边界把账号名整串写入建议归属措辞（构成无法满足的死约束）、对自述创作方法设归属要求；评审判据退化为「主体+转述动词」词法匹配；程序侧词法标记不做前置核对、无条件覆盖评审模型的合格结论 |
| 影响指标 | 归属类误拦率（全库反向统计：126 条人工可用中 74 条被拦，59%）；单视频交付率；重写轮次与模型调用成本 |
| 最终修复 | 四步递进：边界措辞规范化 → 评审判据单标准 → 程序预判下发 → 标记前置核对 |
| 回归结果 | 离线回归 942 项全部通过；终验两条通过自动评审；人工三条全部可用（当日完成） |

### 复盘过程

**第一步：确认问题的量级。** 现象是九条候选被拦、人工全部判可用——但单视频的反差还不足以定位问题，先要确认它是孤例还是系统性的。排查方法来自用户确立的方向：不盯被拒的坏标题，而是**把人工判为可用的标题全部拿出来，反向核对系统对它们判了什么**。全库统计结果：261 条可匹配的人工判定中 126 条可用，其中 74 条被系统拦截，误拦率 59%；拦截理由里「来源归属缺失」占 25 次、「限定缺失」占 23 次，另有 19 条实为评审输出结构失败、被错误计入了标题缺陷。这个数字确认了问题性质：判定规则系统性过严，本案只是最典型的一个切片。

**第二步：第一层排查与第一个假设——评审判据过严。** 从拦截理由出发，最先被检查的是评审的归属判据。当时的判据实际上是词法匹配：标题里必须出现「某人+称/表示/报道」这样的转述句式才算「标注了来源」。但按人工口径——「读者会不会把这条标题当成官方通报、已核实的事实或他人的原话」——标题里出现「博主」、出现「商业观察」、或用了「演示/教学」这类词，读者已经知道这是谁在说、在做什么，不存在误认风险。同时检查边界的输出，发现两个伴生问题：它把创作者账号名「感性城市SCity」整串写进了「建议归属措辞」字段（该字段的语义是「标题宜出现此词」，账号名装不进 20 字标题，等于下了必死约束）；博主自述拍摄手法这类无警示必要的陈述也被设了归属要求。

**第三步：修复第一层并验证——部分有效，暴露了更深的层。** 按第一层发现修改：边界侧规范措辞（个人账号一律用「博主」通称、自述方法不设归属要求），评审侧把归属判据收敛为「读者是否会误认」单一标准，同时让程序先做一次字面核对、把「标题里有没有归属线索」作为事实随材料下发给评审。隔离批次验证：教程类视频三条候选全部恢复合格（它的问题正是「自述方法被设归属要求」）；美食类视频两条恢复（「美食博主演演白菜焖法」不再报缺归属）。**但小包装依然九条全拦。** 两批对照视频恢复了、目标视频没有——说明已修复的两层是真实缺陷但不是根因，下面还有一层。

**第四步：决定性的一步——对照评审的输入与输出原文。** 此时已经改了三轮提示词、修了两层机制，小包装纹丝不动。这个模式本身成为线索：**提示词反复调整都无法改变模型行为时，应该怀疑模型的行为根本不是最终行为——它可能被程序覆盖了。** 于是调取评审阶段的输入快照与输出原文逐条比对，得到两个事实：其一，评审模型对最近数轮的判定实际是**合格**，理由原文为「标题以『博主』归属作者观点，未写成已证实规律；小包装小样成热点为博主分析框架，有ASR与简介支持」；其二，程序侧存在一条词法强制标记的生成逻辑——以「主体+转述动词」为判据复查每条候选，「博主拆解」的「拆解」不在其动词表内即未命中，于是注入「来源归属缺失」标记；后续的程序裁决环节**无条件地用该标记改写了评审模型的合格结论**。既含「商业观察」又含「博主」的候选之所以也被拦，正是这一机制所致。根因至此定位：不在模型，在程序裁决层。

**第五步：确定根治方案。** 在前两层修复之上增加根治项：程序在注入「来源归属缺失」标记之前，先执行一次归属线索核对——建议措辞的主体词出现、身份称谓、内容性质前置、演示动词，任一命中即视为归属已表达、不注入标记。评审模型的合格结论自此不会被程序改写；同时保留防线——只有纯断言式标题（如「小包装比大包装好卖」，无任何身份或性质线索）才照常注入标记。

**第六步：小流量测试与放量。** 增补根治项后复测小包装：三条候选中两条通过自动评审、任务正常交付，第三条因「标题承诺的问题视频未真正回答」转入重写——该判定方向正确，属质量把关而非误拦；离线回归 942 项全部通过。当日终验批次人工复核，三条全部判定可用，终稿「商业观察：小包装走红背后的消费逻辑」**原样采用了系统通过评审的候选二**——系统合格判定与人工最优选择完全重合。本案闭环。

## 4. 跨案例经验

**一、真凶不在最先被怀疑的地方。** 案例一最初怀疑「提示词没写清楚」，实为缺强制核对结构；案例三改了三轮提示词才定位到程序裁决层的覆盖行为。两案共同的定位手段都是**调取输入与输出的原文做对照**，而不是继续猜测。

**二、「改提示词」是最容易尝试也最容易无效的路径。** 案例一有对照实验证据（同样提示词下问题标题三连放行）；案例三轮换三版判据都拦不住程序标记。机制层面的缺陷需要机制层面的修复。

**三、多层问题分步修、逐步验证。** 案例三的四步修复中，每一轮小流量测试都同时完成两件事：验证已修层的效果、暴露下一层的存在。若一次性改完所有层，最终成功无法归因，中途失败无法定位。

**四、人工复核的拒绝理由是修复需求的主要来源。** 超长隔离源于「字数超了就不要送来」；承诺对照结构源于「视频展示的是表态不是分析」；归属预判源于「商业观察已经说明了这是观点」。三案九个修复项中七个可以追溯到人工反馈里的一句具体的话。

**五、修复完成的判定标准是「人工认可的标题出现在系统合格候选池中」。** 三案的终稿全部落在系统合格候选池内；但系统推荐排序与人工首选的重合仅一例——候选池质量与推荐排序是两个独立问题，后者是后续优化项。

## 5. 如实说明

1. **三案闭环成色不同。** 小包装为唯一以「当日最终代码 + 当日复测 + 当日人工复核」完成全程闭环者；萨戈夫闭环于四日前代码、南非闭环于两日前代码，最后合入的归属放宽未在这两条视频上回访复测。风险为低（两案的标题分别具有明确转述句式与具体事件主体，新旧判据均放行），但形式上缺最后一环。
2. **误拦率改善的外推边界。** 59% 误拦率为修复前全库统计；三案及其对照视频的隔离批次实测不构成全量收敛的证据，需不少于十条视频的批次复测后方可宣称。
3. **残余分歧（系统更严方向）。** 小包装候选三被系统判「承诺未兑现」转入重写、人工判可用。不属误拦，留作评审判据校准的观察样本。
