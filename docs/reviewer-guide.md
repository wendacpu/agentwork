# 人工评审卡（Reviewer Guide）

> 你判的是这条标题能不能用，不是系统判得对不对。先独立看标题和视频材料，不看系统路线、推荐、分数或推理。
> **评审前先读 [锚点样例](../templates/anchors.md)**；锚点定义判档边界。具体样例编号与条数以当前文件为准。

## 你要做的事

只做两件事：
1. 选一个结果：**可用 / 勉强通过 / 不可用**。
2. 「勉强通过」和「不可用」各写一句观察到的问题；问题判据归类可选，不确定就留空。

不需要提出改写方案，不需要区分问题来自表达、ASR、OCR、Boundary 还是看点提取。描述实际问题即可，AI 后续结合候选和上游证据分析根因。不要填写你没有把握的归因。

## 三档标准

| 判定 | 标准 | 一句话判据 |
|---|---|---|
| **可用** | 标题准确、清楚，能兑现视频主要内容，可以直接用。 | 不用改一处 |
| **勉强通过** | 基本准确且可用，但存在明确瑕疵；必须写出瑕疵，不要求提供怎么改。 | 只差局部一处（缩写要展开、某个词要换） |
| **不可用** | 标题不能使用。写出读者可能误解的内容、与视频重点不符之处，或其他可观察的问题即可。 | 要换看点/补事实/改方向，一处修改救不回来 |

分歧高发在「勉强通过 vs 不可用」。判的时候问一句：**改这一处之后，读者对视频的预期会不会变？** 会变 → 不可用。

三档只是人对标题的判断。AI 决定是否以及如何重写；人不需要选择“需改写”。

## 关于平台标注前缀

标题前可能出现 `【剧情演绎】`、`【AI生成】` 等标注；它们是否由程序自动添加、以及计长规则，请以当前实现与任务输出为准。

- 判 **可用 / 勉强通过 / 不可用** 时，以前缀之后读通不通、正文是否准确为准。
- **不要因为"前缀不好听/太生硬"就降档**——措辞不归你判。
- 但要判一种情况：**去掉前缀正文就读不通**（例如正文以"的""是"开头），这属于结构问题。
- 正文重复前缀已说明的属性（`【剧情演绎】剧情演绎…`）算瑕疵，判「勉强通过」并写明"前缀重复"。

## 盲评原则

提交之前只看标题和必要的原始材料。先形成自己的判断；不得参考系统路由、推荐候选、评分、问题清单或模型推理。长度上限、问号结尾、引用合法性等 G4 机械检查由程序负责，不需要人工计数或复核。

## 如何写理由

- 写具体观察，不写空泛标签：例如“视频重点是作者长期健身练薄肌，不是演示 U 型臂力器”。
- 不确定问题来自标题表达还是上游看点理解时，直接描述偏差，不要猜根因。
- 「勉强通过」需明确指出瑕疵；无需给出新标题或修改建议。
- 可选问题归类只是帮助后续检索，不是必答项；选错比留空更糟。

## 评审结果如何使用

人工结果用于形成评估标签，落盘位置及覆盖、撤回行为应以当前实现为准。它是经人工确认的样本，不是绝对真理；统计时应只计入当前有效标签，避免把历史操作重复计数。
