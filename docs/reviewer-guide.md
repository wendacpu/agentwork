# 人工评审卡（Reviewer Guide）

> 你判的是这条标题能不能用，不是系统判得对不对。先独立看标题和视频材料，不看系统路线、推荐、分数或推理。

## 你要做的事

只做两件事：
1. 选一个结果：**可用 / 勉强通过 / 不可用**。
2. 「勉强通过」和「不可用」各写一句观察到的问题；问题判据归类可选，不确定就留空。

不需要提出改写方案，不需要区分问题来自表达、ASR、OCR、Boundary 还是看点提取。描述实际问题即可，AI 后续结合候选和上游证据分析根因。不要填写你没有把握的归因。

## 三档标准

| 判定 | 标准 |
|---|---|
| **可用** | 标题准确、清楚，能兑现视频主要内容，可以直接用。 |
| **勉强通过** | 基本准确且可用，但存在明确瑕疵；必须写出瑕疵，不要求提供怎么改。 |
| **不可用** | 标题不能使用。写出读者可能误解的内容、与视频重点不符之处，或其他可观察的问题即可。 |

三档只是人对标题的判断。AI 决定是否以及如何重写；人不需要选择“需改写”。

## 盲评原则

提交之前只看标题和必要的原始材料。先形成自己的判断；不得参考系统路由、推荐候选、评分、问题清单或模型推理。长度上限、问号结尾、引用合法性等 G4 机械检查由程序负责，不需要人工计数或复核。

## 如何写理由

- 写具体观察，不写空泛标签：例如“视频重点是作者长期健身练薄肌，不是演示 U 型臂力器”。
- 不确定问题来自标题表达还是上游看点理解时，直接描述偏差，不要猜根因。
- 「勉强通过」需明确指出瑕疵；无需给出新标题或修改建议。
- 可选问题归类只是帮助后续检索，不是必答项；选错比留空更糟。

## 评审结果如何使用

人工结果会覆盖写入 `templates/gold.csv`，作为后续评估 Agent 的参考标签；它是经人工确认的评估样本，不是绝对真理。撤回后可以重新判定，撤回会移除对应的当前金标准行和当前决策标签，重判后写入最新结果。历史操作审计可保留在运行事件中，但不能当成当前标签重复计数。
