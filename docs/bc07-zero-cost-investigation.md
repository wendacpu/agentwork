## 根因边界

历史评审的明确偏差是：把关于自身强弱的解释认作关于对方传奇地位的答案；用户认为读者期待与采访核心存在偏差。原始评审输出两项均为 true，故不能证明它当时触发了下面的布尔矛盾缺陷。当前版本语义是否仍漏判，必须用真实模型复测，不能凭离线测试宣称。

现行程序另有可独立复现的契约缺口：当 G3 `status=pass` 而 `delivery_supported=false` 时，旧程序只纠正 `core_covered=false`，没有纠正前者；同等其余输入下会被判 `ready_for_human_review`。这是反事实结构探针，不是 BC07 原始模型输出。现改为两个明确 false 都不得被 pass 覆盖；保留 needs_review/reject，不把关键词或缺字段当成语义判断。未兑现走 N09 表达修复，明确核心遗漏走 N07；若两者同时成立，优先保留核心遗漏的回退线索。提示词补充受访者解释与客观分析的区分，不机械禁止疑问句。

## 本次验证边界

`tests/test_bc07_review_contract.py` 用模拟评审结果测试两个字段的矛盾、双失败、较严格状态及正常标题不被疑问词机械拦截：定向 8 项通过；全量 `python3 -m pytest -q -p no:cacheprovider` 为 678 项通过。通过仅说明程序接线，不证明模型能否正确理解视频。

**真实模型复测已完成，结论是问题仍在**：原视频端到端重跑再次生成同一句错误标题，评审把两项判断都写成“已兑现”，状态 `ready_for_human_review`，人工判不可用。程序兜底只在明确写 false 时生效，防不住两处都判 true。复测同时发现正常新闻样本三条全部被 `G1_*` 规则误拦。完整数据、口径与局限见[BC07 真实模型复测报告](bc07-evolink-retest.md)。历史结果与本轮结果不得混写。

局限：评审如果把两项错误地都判为 true，程序无法凭这两个布尔字段自行识别语义错误；旧模型缺失两项布尔时目前保持兼容，不应表述为已强制完整输出。复测已证实这一局限真实发生，不是理论风险。
