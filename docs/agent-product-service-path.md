## 0. 一页速览

| 项 | 内容 |
|---|---|
| 做什么 | 给定一条 B 站竖屏视频（素材 + ASR + OCR + 标题），生成 ≤3 条推荐标题，并独立评审、给出可追溯的拦截理由 |
| 给谁用 | 短视频平台的推荐/审核环节；本版是离线实验，不接线上流量 |
| 核心主张 | **规则约束 + 独立评审**能在不依赖人工的情况下拦住不合格标题 |

| 自主度 | **0 个自主调度 Agent**（详见第 4 节）；这是设计选择，不是能力缺失 |

| 下一步 | 配好业务政策重跑 → 15 条金标准 → 出 4 个数 → 再改规则（第 10 节） |

## 1. 项目背景与问题

### 1.1 业务痛点

短视频平台的推荐文案（标题）有三个互相冲突的约束：

1. **要有吸引力**——决定点击；
2. **不能失真**——不能把转述写成事实、把观点写成结论、把局部写成完整；
3. **要短**——竖屏信息流里通常 20 字以内。

人工写靠经验，规模上不去；纯模型写会为了吸引力牺牲真实性，且**错了没人说得清错在哪**。

### 1.2 现有做法的缺陷

| 做法 | 缺陷 |
|---|---|
| 人工写 | 一致率低、不可规模化、经验无法沉淀 |
| 端到端生成模型 | 输出不可审计；无法定位"是理解错了还是表达错了" |
| 规则 + 模板填空 | 覆盖不了语义判断（"这句话算不算被支持"）；表达僵硬 |
| 单纯加 Prompt 约束 | 约束是软性的，模型可以遵守也可以不遵守，且没有独立复核 |

### 1.3 可量化目标

**线上业务指标（本版不可得）**：CTR、完播率、举报率、审核驳回率。

**本版使用的替代指标（必须显式声明，见第 9 节）**：

| 指标 | 定义 | 目标线 | 现状 |
|---|---|---|---|
| 一次通过率 | 同一视频至少 1 条候选被人工判"可用"的比例 | 待金标准确定 | 1 视频，样本不足 |
| 人工一致率 | 系统推荐的候选与人工实际选择一致的比例 | ≥ 80%（暂定） | **0 条可比** |
| 长度合格率 | 候选 ≤ 20 字的比例 | ≥ 90% | 100%（9 条候选）；但真实历史运行 19% 超长 |
| G1 漏拦率 | 人工判"事实有问题"但系统 G1=pass 的比例 | ≤ 10%（暂定） | **100%（1 条对照）** |
| 结构校验通过率 | 模型输出通过 schema + 引用白名单的比例 | 100% | 100%（29 个单测覆盖） |

目标线均为待金标准验证的暂定值，**不是已达成值**。

### 1.4 本版定位

这是一个 **(a) 能证明"规则约束 + 独立评审"是否有效的离线实验**，不是 **(b) 可交付业务使用的系统**。

判据：没有线上流量、没有真实用户反馈、人工闭环只判过 1 条视频。因此"做完"的定义不是界面和全量跑通，而是**能报出上表 4 个数字并能对比两个版本**。

## 2. 产品设计

### 2.1 服务路径（纵向五层）

参考图 `_ref/懂车帝复杂 agent 产品.md` 是横向按业务环节切（准入→尽调→审查→审批→放款）。本项目**不横向切**，因为那条链路 30 秒内跑完，没有岗位/时间边界，硬切是"为切而切"。

改按**纵向分层 + 责任域分块**：

```
L1 输入层    视频素材（mp4）｜ASR ｜OCR ｜抽帧 ｜主表字段（领域/形态/时长/画幅）
                │
L2 横切编排   规则包 U/V/F ｜业务政策 P1–P3 ｜G4 机械校验 ｜Q01 程序裁决
                │（跨域，不属于任何 Agent；Q01 是唯一总决策者）
                ▼
L3 Agent 域   ┌── A 理解域 ──┐ ┌── B 表达域 ──┐ ┌── C 裁决域 ──┐
              │ N03→N04→N05  │ │ N07→N08→N09  │ │     R01      │
              │ →N06         │ │ →N10→N11     │ │              │
              └──────────────┘ └──────────────┘ └──────────────┘
                │ 输出 BoundarySet │ 输出 Candidate[≤3] │ 输出 ReviewGate+issues
                ▼
L4 人工层     H01 人工确认（采用 / 驳回 / 人工重写）→ case 固化
                │
L5 数据资产   判据库(20)｜金标准(gold)｜bad case 库｜规则包｜事件日志｜案例库
                └──── 回流箭头：改规则 / 改 Prompt / 改判据 → 回到 L2、L3 ────┘
```

**与原参考图的三处差异**：
1. 它把"规则/编排"画成中间一层但每个 Agent 内部也带规则；本项目把机械校验和程序裁决**上提到横切层**，保证"评审不判自己"。
2. 它有 5 个人工确认闸门；本项目只有 1 个（H01），所以只画 1 个，不虚增。
3. 它有从左到右的单向流程；本项目多一条回环（L5→L2/L3），这是"越用越好"的实体。

### 2.2 三个 Agent 域

切分依据不是节点数，而是**失败方式唯一 + 指标唯一 + 修复手段唯一**：

| 域 | 节点 | 回答的问题 | 输入契约 | 输出契约 | 唯一失败方式 | 指标 | 修它改哪 |
|---|---|---|---|---|---|---|---|
| **A 理解** | N03→N04→N05→N06 | 这条视频里**有什么能写** | `VideoInput` + `Evidence[]` | `BoundarySet`（claims + usable/limited/excluded + 限定 + 核验任务） | 判错 / 漏拦 | G1 漏拦率、claim 引用合法率 | `rulepacks/common.md` U 条 |
| **B 表达** | N07→N08→N09→N10→N11 | **怎么写** | `BoundarySet` + `HighlightSet` + 规则切片 | `Candidate[≤3]` + 机械检查结果 | 写超 / 丢限定 / 主看点错 | 长度合格率、一次通过率 | `prompts.py`、策略枚举、看点选择 |
| **C 裁决** | R01 | **写得行不行** | 候选 + 原始材料 + 边界 + 规则切片 + 机械结果 | `ReviewGate`(G1–G3) + Q1–Q3 + `issues` + 改写指导 | 放水 / 过严 | 人工一致率 | `criteria.csv`、rubric |

**为什么表达域不拆成"看点 / 生成"两个包**（已确认）：两者共享同一批边界与同一组指标，拆开后没有任何一个失败模式或修复手段是独立的；拆分只会让"为什么这是两个 Agent"无法回答。

**为什么裁决域不含 Q01**：Q01 是 Gate 聚合与路由，属于横切编排层。放进来就等于"评审自己判自己"，与 F3 三段分离原则冲突。

### 2.3 核实策略分级表（新增，当前缺失）

这是本项目最重要的一个**缺口**，也是一个决策点（见 4.4 D11）。

现状：`attribution_required`（标题是否必须写来源）和 `verification_required`（是否暂缓核验）**完全由 N05 模型逐条判定，Prompt 中没有任何品类条款**。结果是：娱乐、剧情、表演类视频也会被要求归属，产生两个副作用——

1. 生成被迫带"据…"前缀，**直接推高字数**（真实运行 19% 超长的候选，恰好都是"据通报 + 主体 + 数字"这类正确归属表达）；
2. 归属要求在没有信源价值的场景里是噪音，反而降低标题质量。

**应按「内容形态 × 内容领域」查表，而不是让模型逐条自由判**：

| 形态 | 领域 | 核实要求 | 理由 |
|---|---|---|---|
| F11 资讯播报 | 资讯（时事社会/财经/科技等） | **强制**：必须可识别信源，冲突须暂缓核验 | 涉及真实事件与他人名誉 |
| F02 讲解分享 | 知识科普 / 健康运动 | **强制**：事实类陈述须归属或限定，观点须标注 | 易被当成专业结论 |
| F03 测评试用 / F05 探店 | 消费相关 | **条件**：涉及数据/对比须归属 | 有商业误导风险 |
| F09 剧情短片 / F08 表演展示 | 泛娱乐 / 生活记录 | **豁免**：不要求归属；只需标注虚构/演绎属性 | 不涉及真实事件核实 |
| F06 成果展示 / F07 现场记录 | 美食 / 生活 / 宠物等 | **豁免**：只约束"画面可见"与"不得推断" | 无信源概念 |
| 任意 | 任意 | 若 claim_type=opinion/prediction | **条件**：须保留归属或标注为主观 | 与形态无关 |

落地方式：`rulepacks/common.md` 增加一条 `U-S08 核实要求按形态分级`，N05 Prompt 引用该表；程序侧对"豁免类却被要求归属"给出 warning（可观察，不阻断）。

**这不是"让模型少做事"，是把一个不该由模型做的元决策收回到规则层。** 详见 4.4。

## 3. 模块说明

每个模块按参考图的五元组写：**组件构成、输入、输出、判据依据、失败模式与兜底、指标**。

### 3.1 A 理解域 Agent

**职责**：把一次视频任务变成"哪些事实可写、带什么限定"的清单。它是唯一的"事实边界"来源，下游全部依赖它。

| 组件 | 做什么 | 谁判 | 输出字段 |
|---|---|---|---|
| 材料装配 | 合并 ASR/OCR/画面/标题，去重，保留定位 | 代码 | `Evidence[]`（含 quality 标注） |
| 事实抽取 | 从材料里抽出 0–N 条原子陈述，标注类型/时态/断言权限/传播链 | 模型 S1 | `Claim[]` |
| 规则切片 | 按领域+形态+属性选 U/V/F 规则 | 代码 | `RuleBundle`（含 match_trace/gaps） |
| 边界判定 | 逐条判 usable/limited/excluded，写必要限定、禁止推断、核验标记 | 模型 S1 | `BoundarySet` |
| 可写路由 | 全部 excluded 且需核验 → 停止并产出核验任务 | 代码 | 任务状态 |

**输入**：`VideoInput`（`title / asr_segments / ocr_segments / evidence / domain / format`）+ `RuleBundle`
**输出**：`BoundarySet`（`decisions[]` 含 `claim_type / evidence_status / temporal_status / assertion_permission / required_limits / forbidden_inferences / attribution_required / verification_required`）

**判据依据**：`rulepacks/common.md` U 条（30 条，含 U-S01 信源、U-S02 归属、U-T01/02 时态、U-H04 限定、U-B06 长度）+ 2.3 核实分级表

**失败模式** | **兜底**
--- | ---
漏抽事实（该写的没抽） | 下游无从发现；只能靠 G3"承诺未交付"间接暴露——**目前无直接兜底**
编造事实（不在 evidence 里） | `evidence_refs` 白名单程序校验，非法 ID 直接判错
把历史写成当前 | 程序 `programmatic_g1_flags` + R01 复核 + 人工
归属要求过度（娱乐类也被要求带来源） | **当前无兜底**，见 2.3
规则缺失（领域覆盖仅 38%） | 记 `gaps` 继续，不静默；但等于只有通用规则

**指标**：G1 漏拦率（未测）、claim 引用合法率（100%，29 单测覆盖）、领域规则覆盖率（实测 38%）

### 3.2 B 表达域 Agent

**职责**：在边界允许的范围内，选一个看点、选一种策略、写出 ≤3 条 ≤20 字的候选。

| 组件 | 做什么 | 谁判 | 输出字段 |
|---|---|---|---|
| 看点选择 | 选 1 主 + ≤2 备，写代表性依据与淘汰原因 | 模型 S1/S2 | `HighlightSet`（含 `eliminated[]`） |
| 上下文装配 | 拼装 看点+边界+规则切片+案例+策略枚举+字数限制 | 代码 | 生成入参 dict |
| 案例检索 | 按 issue_code/标题查历史案例（最多 6 次） | 代码触发 | `memory_cases`、`memory_trace` |
| 候选生成 | 产出标题 + 引用的 claim/highlight/evidence + 策略 + 限定表达 | 模型 S1 | `AgentDraft` |
| 机械校验 | 长度 / 问号结尾 / 引用白名单 / 策略与材料不符 | 代码 S0 | 错误码列表 |
| 交付路由 | 按 Gate 与 Q 分聚合出 handoff/needs_review/rewrite/reject | 代码 S0 | `route` |

**输入**：`BoundarySet` + `HighlightSet` + 规则切片 + 案例
**输出**：`Candidate[≤3]`（`headline / claim_ids / evidence_ids / highlight_id / expression_strategy / qualifiers_used / used_case_ids`）

**判据依据**：`criteria.csv` C07–C09（交付类）、C11–C13（机械类）、C14–C16（质量类）、C18（策略）、C20（术语展开）

**失败模式** | **兜底**
--- | ---
超长（20 字上限） | G4 机械拦截 → 重写 ≤2 轮
丢失必要限定 | R01 判 C06 → G1 issue → 回 N09 重写
主看点选错 | R01 判 C08 → G3 issue → **切 `rewrite_mode=看点`**，允许改 highlight
引用非法 | 白名单程序校验直接判错
结构漂移（模型不给合法 JSON） | 8 组归一化别名 + schema 校验 + 重试上限
重写耗尽仍不合格 | 停止（`stopped`），候选仍可被人工判——不静默丢弃

**指标**：长度合格率（100% / 9 候选；历史真实运行 19% 超长）、一次通过率（待金标准）、重写有效性（resolved/repeated，**目前 0 个可比轮次**）

### 3.3 C 裁决域 Agent

**职责**：独立于生成方，判决每条候选是否可用，并给出可归因的问题清单。

| 组件 | 做什么 | 谁判 | 输出字段 |
|---|---|---|---|
| 独立评审 | 对照原始材料 + 边界 + 规则切片 + 机械结果，判 G1–G3 与 Q1–Q3 | 模型 S1 | `ReviewGate` + `issues[]` + `rewrite_guidance` |
| 问题归因 | 每条 issue 记 `primary_dimension / issue_code / rollback_to` | 模型+程序 | `issues[]`（可下钻到 N05/N07/N09） |
| 程序复核 | schema 校验；G4 与总决策由程序做；Q 分不得抵消硬问题 | 代码 S0 | 最终状态 |

**输入**：候选 + 原始材料 + `BoundarySet` + 规则切片 + 机械检查结果（**不读生成方自评**）
**输出**：G1（事实）/ G2（政策）/ G3（交付）三态 + Q1（清晰）/ Q2（完整）/ Q3（精彩）分数 + `issues[]`

**判据依据**：`criteria.csv` 20 条判据（每条含定义/反例/归属 Gate/判定者/回退节点）

**失败模式** | **兜底**
--- | ---
放水（判 pass 但人工判不可用） | 金标准比对（**唯一对照 4 条候选，放水 4/4**）
过严（判 revise 但人工判可用） | bad case BC02：重写耗尽但候选其实不差
政策违规漏判 | G2 命中已批准 policy 的 rule_id → 程序 `reject`；未命中但报 reject → 降级 needs_review
评审格式非法 | schema 校验 → `REVIEW_SCHEMA_INVALID` → needs_review

**指标**：人工一致率（**0 条可比**）、G1 漏拦率（100%/1 条）、G1 误拦率（未测）

## 4. 决策登记与自主度审计

### 4.1 为什么需要这套分级

行业里"Agent"一词最常见的误用是把**调用模型**说成**自主**。两者差别决定了一个系统能否被信任：

- 调用模型 = 在固定的执行路径上，某个位置替换成模型生成 → 行为可预测、可测试、可审计；
- 自主调度 = 模型自己决定下一个动作 → 行为空间不由代码定义，需要更强的护栏与更严的验收。

本项目必须把自己的真实档位说清楚，否则第 1 节的"可量化目标"就失去意义（你无法验收一个行为空间未定义的系统）。

### 4.2 四级定义

| 级别 | 名称 | 判据 | 可测试性 |
|---|---|---|---|
| **S0** | 确定性 | 能写成 if-else，输入相同则输出必相同 | 单测 |
| **S1** | 生成 | 模型产出内容/判断，但**动作由代码固定**（一次调用、无后续动作选择） | 固定输入回归 |
| **S2** | 枚举内选择 | 从代码/rubric 定义的有限集合里选一个 | 选项覆盖测试 |
| **S3** | 自主调度 | 模型自己决定要不要调工具、调什么、调几次、走哪个分支 | 需要轨迹级验收 |

### 4.3 已登记决策点的实际档位

| ID | 决策点 | 登记为 | **核验后实际** | 依据 |
|---|---|---|---|---|
| D01 | 抽哪些事实 | 模型 | S1 | 一次调用产出 claims，动作固定 |
| D02 | 能否写/带什么限定 | 模型 | S1 | 三档状态由语义定，无动作选择 |
| D03 | 选哪个主看点 | 模型 | **S1** | 看点是同一节点产出（含 eliminated），不是从外部集合里选 |
| D04 | 要不要检索/用什么词 | 模型（原记"唯一自主"） | **S1，且为伪自主** | 见 4.4 |
| D05 | 用哪个表达策略 | 模型 | **S2** | `STRATEGY_ENUM` 5 个写死 |
| D06 | 机械约束 | 程序 | S0 | 长度/格式/引用纯计算 |
| D07 | 推荐哪条 | 程序 | S0 | 按 Q 分和排序 |
| D08 | 是否合格 | 模型 | S1 | 三 Gate + 三维分，动作固定 |
| D09 | 走 handoff/rewrite/停 | 程序 | S0 | Gate 聚合 |
| D10 | 最终采用 | 人工 | 人工 | 背责动作 |

**结论：S3 数量 = 0；S1 = 5（D01/D02/D03/D04/D08）；S2 = 1（D05）；S0 = 4（D06/D07/D09 + N04 规则路由）；人工 1（D10）。**

这不是缺陷。标题生成的动作空间（抽事实→判边界→选看点→写→评）是可穷举的固定序列，让模型自己规划只会增加不可控性，而收益为零。**克制是设计，不是没能力。**

### 4.4 核验发现的三类问题

#### ① 伪自主：D04 案例检索

原登记写"检索词取决于问题类型，无法预先枚举；这是本项目唯一真正的自主调用"。

**代码核验（`pipeline.py` 的 `_generate_and_review`）显示**：

- 触发条件 = `memory_calls < config.memory_call_limit`（6），即**代码无条件触发**，不由模型决定"要不要检索"；
- 首轮生成的 query **缺省等于 `video.title`**，`problem_types` 写死为 `["表达", "事实与信源"]`；
- 重写轮才使用评审返回的 `memory_query`，没有就用 `issue_code` 拼接；
- 检索本身是中文 2-gram 词匹配（`memory.py`），不是语义检索。

**真身**：一个由代码定时触发、查询词有确定性缺省值的词表检索，模型最多提供一个提示。**S1，不是 S3。**

连带影响：`used_case_ids` 在全部真实运行中从未出现（`cases` 表仅 1 条且记在 `temporary-v1` 版本下），因此"经验回流"目前是**未通电的电路**。

**处置**：`decision_register.csv` D04 应改登记为"代码触发 + 模型可选提示"，并从"自主调用"降级；`cases` 表清空重建。

#### ② 漏登：四个必须判但没人登记的决策点

| 新增 | 决策点 | 现在怎么做 | 该谁判 | 为什么 |
|---|---|---|---|---|
| **D11** | 这条视频**要不要做可信度/归属核实** | 没有这个决策；N05 对所有视频用同一套标准，Prompt 无品类条款 | **规则 S0**（查 2.3 表） | 娱乐/剧情/表演类不涉及真实事件，强制归属是噪音且推高字数。品类字段已有，不需要模型 |
| **D12** | 无领域规则命中时怎么办（62%） | 静默继续，只记 `gaps` | 规则 S0 + 人工补规则 | 不是模型问题，是规则体系问题；但必须显式标记"本条只有通用规则" |
| **D13** | 素材不足时怎么办（18 条空 ASR） | 只统计不处理 | 规则 S0 | 证据不足应降级（只允许画面可见事实）或停止；现在等于不判 |
| **D14** | 某条判据是否因品类不适用而豁免 | 没有；20 条判据全局生效 | 规则 S0（查 C 表） | C10/C19/C20 应按品类适用，否则娱乐类会被"信源权威性"误伤 |

**D11 的作用边界（已修正）**：它只解决"该不该带归属"，**不解决长度**。长度是独立硬约束（见 5.3），归属前缀同样计入字数。两者叠加后的正确结论是：娱乐/展示类本就不该带归属 → 自然变短；资讯/科普类必须归属 → 必须在 20 字符内压缩归属表达（"据通报"而非"据康平县调查组通报"）。**19% 超因此从"口径问题"降级为"生成质量问题"，由重写解决，不放宽上限。**

#### ③ 待重判：D03 与 D05

| 项 | 问题 | 建议 |
|---|---|---|
| D05 策略选择 | `criteria.csv` C18 已经说明"策略与材料不符"可机械校验（无方法却用问题方法）。**既然能事后校验，就能事前规则化** | 前移到规则：材料有步骤 → 允许"问题方法"，否则只允许"直接描述"。模型只负责写，不负责选。减少一个不稳定点 |
| D03 看点选择 | 看点是 N07 一次产出的（含 `eliminated[]`），不是从既有集合里挑 | 归入 S1，不再单列为 S2；但保留"淘汰原因"字段用于归因 |

### 4.5 对外的正确说法

> 三个 Agent 域，**零个自主调度 Agent**。5 个 LLM 调用点是固定的生成与判断，1 处策略选择在 5 个枚举内，4 个关键裁决由代码做（机械校验、推荐排序、路由、终态）。唯一接近自主的案例检索，核验后是代码定时触发的词表检索，已降级。这个结构是设计出来的：标题生成的动作空间可穷举，自主规划只增加不可控性。

这句话比"我做了 3 个 Agent"值钱，因为 `decision_register.csv` 能提供全过程证据。

### 5.3 判定口径（2026-10-30 业务方确认）

#### 长度：≤20 字符，无豁免

NFC 后 Unicode 码点数 ≤ 20 为唯一口径。**归属前缀（据…称/通报/表示）同样计入字数，不做扣减，不设 24 字放宽。** 这与"要不要带归属"是两件独立的事：

- 该不该带归属 → 由 2.3 核实分级表决定（娱乐/展示类不带，资讯/科普类必须带）；
- 带了之后多长 → 一律 ≤20。资讯类的正确做法是压缩归属表达（"据通报"而非"据康平县调查组通报"），压不进去就换策略（去掉归属、改直接描述）。

冲突时的优先级：**长度 > 归属完整度 > 修辞**。生成端在写之前就要按此排序，评审端按 C11 硬判，重写端按"压缩"而非"放宽"修。

#### 三档判定词的含义

`criteria.csv` 的「判定结果」列是给人看的统一口径（代码不读这一列，代码读 Gate 状态与 Q 分）。三档对应的代码路径不同：

| 口径词 | 含义 | 代码怎么落地 | 后果 |
|---|---|---|---|
| **不可用** | 这条不能上线 | Gate fail，或某维 Q < `quality_min_each`(2) | → **重写**；只有命中已批准 policy 的 rule_id 才 `reject` |
| **待人工** | 系统不敢判死、也不敢放行 | **仅** Gate = `needs_review`（G1 未解冲突 / G2 未配政策 / schema 非法） | → 进人工队列，不给推荐 |
| **排序靠后** | 可用，但不该排第一 | Q 分刚好 = 2（不低于阈值） | → 可 handoff，按 Q 分和排名靠后 |

**注意：Q1/Q2/Q3 类判据没有「待人工」通道**——代码里 Q 分低只通往 `rewrite`，只有 Gate 级（G1/G2/G3）才有 `needs_review`。所以判据表填「待人工」只对 G 类有效；Q 类填了是悬空的。这条限制在扩展判据时要记住。

#### C14 / C15 定案

| 判据 | 归属 | 判定结果 | 落地方式 | 业务方理由 |
|---|---|---|---|---|
| C14 指代不清 | Q1 | **不可用** | Q1 分 < 2 → 重写；改到能指代清楚，重写耗尽才停 | 人工一定不通过 |
| C15 空泛无信息 | Q2 | **排序靠后** | Q2 恰好 2 分 → 可 handoff，排名靠后 | 视情况勉强通过 |

C14 的处置是"重写"而非"直接毙"，因为"指代不清"是可修的表达问题（换成主体名即可）；重写两轮仍不清才停止，此时候选仍进人工队列。

**② 无成本数据。** 参考文档用 效果 70% + 成本 30% 加权（art pro2.0 综合 92.5）。本项目连单条任务成本都算不出来，横评无法落地。

| 步 | 内容 | 成本 | 产出 |

| 1 | 成本汇总脚本：读事件里的 usage，出每任务 prompt/completion token 与费用 | 30 分钟 | 横评前置 |

**暂不做**：4 家全跑（额度有限，2 家足够支撑结论）。

## 9. 不适用与替代说明

参考文档有三块本项目**不做**，必须明说，否则会被问穿：

| 参考项 | 本项目 | 为什么 |
|---|---|---|
| 灰度 / AB 实验 | **不做** | 无线下流量入口，无法分流；离线用人工金标准替代 |
| 漏斗行为数据（曝光→点击→停留） | **不做** | 同上 |
| 周度 bad case 看板 | **不做** | 需要持续线上数据；改用离线全量导出 |
| 4 个 Agent 的自主规划 | **不做** | 动作空间可穷举（4.5） |

**替代指标声明（必须记住的一句话）**：

> 一次通过率与人工一致率是**替代指标**，不等价于 CTR。它衡量的是"标题是否忠实、是否值得推荐"，不衡量"标题是否点击率高"。在拿到线上数据前，任何"标题变好会提升 CTR"的表述都是未经证实的推断。
