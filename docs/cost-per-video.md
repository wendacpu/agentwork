# 一条视频生成标题，模型调用要花多少钱

数据来源：`runtime/acceptance_deepseek_20261101_114430/agent.db` 里 20 条视频的**实测** `usage`（159 次成功模型回复），不是估算。
单价来源：DeepSeek 官方定价页（`deepseek-flash` = DeepSeek-V4.1-Flash-1017），按 1M tokens 计。汇率 1 USD = 6.6529 CNY（ECB，2026-10-30）。

## 单价

| 项 | 谷时（USD / 1M） | 峰时（USD / 1M） |
|---|---|---|
| 输入 · 缓存命中 | 0.003 | 0.006 |
| 输入 · 缓存未命中 | 0.15 | 0.30 |
| 输出 | 0.60 | 1.20 |

峰时 = UTC 01:00–04:00、06:00–10:00，周一到周五（中国法定假日除外），换成北京时间是**工作日 09:00–12:00、14:00–18:00**；其余时间（含周末、节假日、夜里）都是谷时，价格减半。峰时 = 谷时 × 2。

## 结论：一条视频多少钱

| 口径 | 谷时 | 峰时 |
|---|---|---|
| **一条视频（全流程，产出 3 条候选）** | **$0.026 ≈ ¥0.18** | **$0.053 ≈ ¥0.35** |
| 平摊到每条候选标题 | ¥0.06 | ¥0.12 |
| 中位视频 | ¥0.15 | ¥0.30 |
| 最差视频 | ¥0.50 | ¥1.00 |
| **平摊到每条"可用"标题**（20 条只成 6 条） | **¥0.59** | **¥1.17** |

"每条候选几分钱"这个数字没有产品意义——没人要候选，要的是能发的那条。**真实成本口径是"每条可用标题 ¥0.6–1.2"**，差距全部来自成品率（30%），不来自单价。

## 整个两臂实验要多少钱

按 8.5–8.9M prompt / 0.6M completion（同一命中率折算）：

| 口径 | 谷时 | 峰时 |
|---|---|---|
| 两臂 40 + 40 条 + 3 条冒烟 | **≈ $1.2 ≈ ¥8** | **≈ $2.5 ≈ ¥17** |

结论：**这次实验在钱上可以忽略**。等预算的收益很低，等的是"值不值得花时间看结果"的判断。

## 花在哪里（按 prompt token 占比）

| 环节 | 调用次数 | prompt 占比 | 均次 prompt |
|---|---|---|---|
| N09 生成 + 重写 | 42 | 37.7% | 34.5K |
| └ 生成 | 18 | 15.9% | 34.0K |
| └ 重写 | 24 | 21.8% | 34.9K |
| R01 评审 | 31 | 25.4% | 31.6K |
| N07 看点 | 18 | 12.9% | 27.6K |
| N05 边界 | 20 | 10.7% | 20.6K |
| N03 理解 | 20 | 9.2% | 17.7K |
| N03V 外部核查 | 28 | 4.2% | 5.8K |

## 冗余在哪（如果按"每条标题的算力"审设计）

1. **重写键是最大的一笔无效支出。** 24 次重写 = 每视频 1.2 次，吃掉 21.8% 的 prompt；而同一批数据里重写的"完全解决"率是 2/13 = 15.4%。花五分之一算力买 15% 的修复率。
2. **评审 31 次（25.4%）在判 20 字标题。** 每次 31.6K prompt，等于让评审员把整份理解重读一遍来判一句话。
3. **缓存命中率只有 34.9%。** 静态规则段没有做成稳定的提示词前缀，同一批 20 条视频的重复开销按理应该几乎全命中。把命中率抬到 80%，输入侧成本直接腰斩（每视频 ¥0.18 → ¥0.09）。
4. 理解三节点（N03+N05+N07）合计 32.8%，这部分是"看得懂"的代价，不是冗余——真删了就是回到当初"找不到核心看点"的老问题。

**判断**：钱上不冗余（不到 2 毛一条视频）；算力结构上有冗余，最该动的是重写链和提示词缓存布局，不是砍理解链。
